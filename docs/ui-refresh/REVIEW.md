# CRM UI and phone reliability review — 4 November 2026

## Result

The CRM now has a shared visual foundation: grouped navigation, one global new-lead action, consistent surfaces, typography, controls, dialogs and metric cards. Phones expose Overview, Leads, Tasks and Customers directly, with every remaining section available from More. Existing roles, CRM writes, quotation engines and server integrations are preserved.

The branch starts from GitHub main `070ef8e`, not the older dirty local TTE folder. This work does not modify the Rajarshi client product or its website.

## Defects addressed

- The old phone header exceeded narrow viewports, and bottom navigation exposed only the first five routes.
- Draggable and page-level floating actions could cover enquiry controls. Creation is now available in the header; tasks remain accessible in navigation.
- Saved tasks/messages/views could deserialize to `null` or an object, then fail during array operations. Scroll preferences and blocked storage could also throw during mount. Reads now validate the expected shape and fall back in memory without clearing stored data.
- Older browsers may lack `AbortSignal.any` or `AbortSignal.timeout`; client login, database requests and payment summaries now use AbortController with cleanup.
- The old error boundary described every render error as an out-of-date release. Stale assets now have an early recovery handler, a cache-busting refresh and a loop guard. Ordinary render failures and offline states have accurate recovery actions. Signing in again clears authentication keys only.
- Entry HTML and the recovery script are served without caching. Styles are built with the app instead of generated by a Tailwind CDN script.
- Modal positioning is independent of route transforms; forms fit the viewport, scroll internally, trap focus and restore it after closing.
- Lead filters collapse on small phones, progress controls show every step, and long lead names wrap. Dashboard, inventory toolbar and hotel-description overflows were corrected.
- Inventory and attendance share the CRM palette. Reminder permissions require an explicit action, and unsupported notification constructors cannot crash the app.

The reported phone failure was not reproduced on the user's physical device. The fixes cover several independently reproducible crash/recovery paths consistent with a returning browser failing while incognito works; this is not a claim that every reported failure had one cause.

## Verification

`npm run build` builds the production frontend and existing API bundle. `npm run test:resilience` runs eight focused checks covering malformed/blocked storage, stale chunks, loop prevention, route preservation, manual fresh reload, cancellation and timeouts. Existing customer-account and financial-lead-filter regression scripts pass.

Browser checks used a localhost-only server and fictional records. The server does not proxy production, and all writes other than the dummy login are rejected. Start it with `npm run build:ui-preview` followed by `npm run preview:ui`; its demo access code is `preview`. Test artifacts and screenshots are under `.ui-qa/` locally and are excluded from Git and deployment.

Verified dashboard, board, list and long-name lead detail layouts at 320, 360, 390, 430, 768, 1024 and 1440px (28 checks). Verified successful inventory, attendance and hotel-rate views at 320, 390 and 768px (nine checks). There is no uncontained horizontal overflow in those checks; boards, wide tables, date tabs and navigation tabs retain deliberate contained scrolling. Other routed sections were checked at 320px. Mobile menu access, lead-panel opening/closing, scrollable creation forms, Escape/focus restoration and persisted dark theme were exercised.

Physical iOS Safari, Android browsers, virtual keyboards and notch insets still need owner/device review. CSS includes safe-area spacing, reduced motion and an ES2020/Safari 14 build target, but responsive Chrome emulation is not physical-device testing.

## Existing baseline failures

The full `tsc --noEmit` check already fails on GitHub main: 41 errors on unchanged source, versus 38 after the Vite environment declarations in this branch. Remaining errors include existing page prop/type issues, legacy verification scripts and Deno edge-function imports/globals being included in the root TypeScript project.

The broad rate-wall verification reports 503,075 checks and 336 failures on both unchanged main and this branch, concerning Nirvana Resort date rows/weekend metadata. The pricing engine was not changed and these failures were not fixed or hidden. Investigate separately before claiming that the entire historical test suite is clean.

## Release

Use the repository's documented pull-request/preview/owner-review workflow. Preview the branch and review it on real staff phones before merging into main. No database migration, webhook cutover, worker change or production credential change is required. Rolling back the source commit restores the previous interface; recovery never clears task or quotation storage.

## Follow-up: remove lead temperature

At the user's request, Hot/Warm/Cold badges, card colour cues, creation controls, filters, grouping and the CSV export option are removed. The dashboard's previous hot-only panel now shows recent active enquiries without a temperature dependency. Forms use the existing neutral backend default, and stored/API fields remain compatible. Old bookmarked URLs, session preferences and saved views have retired temperature filters/grouping removed on read; other filters are retained.

The browser resilience suite now contains nine tests, including this legacy-view migration. No schema or integration changes are required.
